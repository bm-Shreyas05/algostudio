Step backwards through a running program.

AlgoStudio instruments your Python, records every assignment, comparison and call as a typed event, and rebuilds the program's state at any moment — forwards or backwards. The picture you see is inferred from the shape of your data at runtime, not written by hand for each algorithm.

How it works

One pipeline, and every algorithm goes through all of it. Nothing in the chain below knows the name of the program it is running.

  1. 1 · Source Your Python, or one of the bundled algorithms.
  2. 2 · Instrument The AST is rewritten so each sub-expression reports itself.
  3. 3 · Execute In an isolated process under time, memory and event budgets.
  4. 4 · Events A stream of typed records — every one reversible.
  5. 5 · State A reducer folds events into state; its inverse steps back.
  6. 6 · View Detectors read the data's shape and choose how to draw it.

Why this isn't an algorithm visualizer

The usual approach is one hand-written animation per algorithm. That scales linearly with effort and teaches the animation rather than the program. AlgoStudio has no per-algorithm drawing code at all.

Adding an algorithm touches no engine code

A new algorithm is a directory containing source and metadata. No view, no animation, no branch in a switch statement. The same is true of a new language: the frontend is the only layer that knows Python exists.

Reverse stepping is exact, not approximate

Every mutating event carries the old value beside the new one, so stepping backwards applies one inverse in constant time. Nothing is re-executed, and the state you land on is the state that was.

The view is inferred from your data

A dictionary of lists that refer to their own keys is drawn as a graph. A list of numbers becomes an array with pointers. Detectors score candidate shapes; no detector is allowed to ask what the algorithm is called.

What it does not do

A tool that overstates its boundary teaches students to distrust it the first time it fails. So, plainly:

It does not run every Python program

The supported subset is real and finite — and documented, feature by feature, in the capability matrix. Async, metaclasses, multiple inheritance and most of the standard library sit outside it. The app tells you before it runs, not after it fails.

It is not a production debugger

Instrumentation makes programs substantially slower and the event budget stops runaway loops. This is a tool for understanding a program of teaching size, not for profiling a service.

Common questions

The full FAQ covers the engine, the sandbox and the supported language subset in more detail.

Can I run my own code on this site?

Yes, and it never reaches the server. Running a stranger's code on a server needs a container sandbox for every execution, which a free tier cannot provide — so the code runs in your own browser instead, on your own machine. Nothing you write is uploaded, and the server goes on refusing to execute anything it did not ship with.

How is stepping backwards possible without re-running?

Each event that changes state stores the old value next to the new one, so the inverse of a step is a single substitution. Jumping to an arbitrary step restores the nearest checkpoint and replays a bounded number of events, which is why scrubbing the timeline stays responsive on long runs.

Does it use cookies or track me?

No cookies, no accounts, no advertising or tracking scripts. Panel sizes are remembered in your browser's local storage and never leave your device. The privacy policy says exactly what is stored and for how long.
